# Story 3.4: Externalize Decoder Data

## Status
- Done (delivered inside Story 3.3)

## Story
As a Magician, I want the data for my coded language system to be stored in an external file, so that I can modify the codes for a trick without needing to change the Python code.

## Acceptance Criteria
1. A data file containing the coded language system exists. — `corindagpt/knowledge-base/effie_code.csv` (Hadley-style table, recovered from the original project). ✅
2. The decoder module loads and uses this external data file. — Code phrases, categories, and values are all derived from the CSV at load time; nothing is hardcoded. ✅
3. The file path is configurable in `config.yaml`. — `decoder.data_path`. ✅
4. The decoder successfully translates a coded phrase from a transcript via the external file. — Verified live (COOL COULD -> King of Hearts; ALL RIGHT THEN TELL -> row 79). ✅

## Dev Notes
- The decoder was built data-driven from the start (Story 3.3), so this story's scope was satisfied in the same implementation rather than as a refactor. Editing `effie_code.csv` (or pointing `decoder.data_path` at another table) requires no code changes; the table is reloaded when the path changes.
