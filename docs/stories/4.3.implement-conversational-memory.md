# Story 4.3: Implement Conversational Memory

## Status
- Done

## Story
As a Magician-Developer, I want the application to maintain a history of the conversation with the LLM, so that the AI can provide contextually aware responses and remember previous interactions.

## Acceptance Criteria
1. A `conversational_memory.py` module stores user inputs and AI responses. ✅
2. The number of remembered turns is configurable (`memory.max_turns`). ✅
3. History is retrieved before each LLM request. ✅ (all three pipeline paths)
4. History is included in the LLM context. ✅ — passed as proper chat messages between the system message and the new user message, rather than rendered into the PromptTemplate; this is more reliable for modern chat models and keeps the phase prompts clean.
5. After a successful interaction, the exchange is added to memory. ✅

## Dev Notes
- Pre-recorded phrases played from the audio queue are recorded as Effie's own utterances (queue items carry their CSV text), so she remembers everything the audience heard her say - parity with the original project's behavior.
- The raw transcript (not the decoded secret block) is stored as the user side of an exchange, keeping history compact; the answer itself carries the revealed information forward.
- Live-verified: card revealed in turn 1 is recalled in turn 2 from memory alone.
