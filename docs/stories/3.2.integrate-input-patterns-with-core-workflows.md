# Story 3.2: Integrate Input Patterns with Core Workflows

## Status
- Done

## Story
As a Magician-Developer, I want to connect the detected input patterns to the core application workflows, so that I can control the performance with specific actions.

## Acceptance Criteria
1. A "sustained input" event from the handler correctly triggers the full record-transcribe-decode-LLM-TTS workflow. [Source: docs/prd.md#story-32-integrate-input-patterns-with-core-workflows]
2. A "brief input" event from the handler correctly triggers the playback of the next item from the audio queue. [Source: docs/prd.md#story-32-integrate-input-patterns-with-core-workflows]
3. A "compound input" event from the handler correctly triggers the record-transcribe-LLM-TTS workflow that bypasses the decoder module. [Source: docs/prd.md#story-32-integrate-input-patterns-with-core-workflows]
4. The phase transition logic (from Story 2.4) is successfully integrated with its corresponding input pattern in the handler. [Source: docs/prd.md#story-32-integrate-input-patterns-with-core-workflows]

## Tasks / Subtasks
- [ ] Extend abstract handler with raw press/release callbacks (AC: 1, 3)
  - [ ] Recording must begin at press-time, before the pattern is classified; add optional `on_press_raw` / `on_release_raw` callbacks to `KeyboardInputHandler`
- [ ] Decoder seam (AC: 1, 3)
  - [ ] Create `src/services/decoder.py` with a pass-through `decode(text) -> str`; real Hadley decoding lands in Story 3.3
- [ ] Main loop routing (AC: 1, 2, 3)
  - [ ] Raw press: start recording (IDLE -> LISTENING)
  - [ ] SUSTAINED pattern (timer fires mid-hold): mark interaction mode "decode"
  - [ ] COMPOUND pattern: mark interaction mode "bypass"
  - [ ] Raw release with a mode set: stop recording, run pipeline (decoder applied only in "decode" mode)
  - [ ] Raw release with no mode (brief or dead-zone release): discard recording, return to IDLE
  - [ ] BRIEF pattern event: play next item from the audio queue (FR5)
- [ ] Retire legacy InputHandler's F12 role (AC: 4)
  - [ ] Make the primary hotkey optional in `input_handler.py`; keep it solely as the F11 long-press phase-transition listener
- [ ] Verification
  - [ ] Manual: tap -> queue clip plays; hold+speak -> decoded pipeline; double-tap+hold+speak -> bypass pipeline; F11 long-press still transitions phase

## Dev Notes
- The audio queue used for BRIEF playback is the rotating file-based `AudioQueue` already present in `src/services/audio_queue.py`; priority/preload behavior is Story 4.1/4.2 scope.
- Decoder is a pass-through until Story 3.3 ports Hadley's system from the original project (`D:\Synology\Magic\CorindaGPT\decode_hadley.py`). En Rapport was proof-of-concept only and will not be ported.
- The dead zone between `brief_max_ms` (250) and `sustained_min_ms` (600) intentionally emits no pattern; releases in that window discard the recording.
