# Story 3.3: Implement Decoder Module Integration

## Status
- In Progress

## Story
As a Magician-Developer, I want to integrate a specialized decoder module into the main processing workflow, so that my coded phrases can be translated into secret information for the LLM.

## Acceptance Criteria
1. A decoder module exists with a function that accepts a text string and returns a processed text string. [Source: docs/prd.md#story-33-implement-decoder-module-integration]
2. The main application logic calls this decoder on the transcribed text before the text is passed to the `PromptTemplate`. [Source: docs/prd.md#story-33-implement-decoder-module-integration]
3. The workflow triggered by a "sustained input" correctly uses the decoder's output. [Source: docs/prd.md#story-33-implement-decoder-module-integration]
4. The workflow triggered by a "compound input" correctly bypasses the decoder, sending the raw transcript to the prompt. [Source: docs/prd.md#story-33-implement-decoder-module-integration]

## Tasks / Subtasks
- [ ] Port Hadley decoding logic from the original project (`D:\Synology\Magic\CorindaGPT\decode_hadley.py`) into `src/services/decoder.py`
  - [ ] Derive code phrases dynamically from the data file's first column (fixes the original's hardcoded word lists, which matched default.csv rather than effie_code.csv) — this also satisfies Story 3.4 AC2/AC4 ahead of schedule
  - [ ] Longest-match phrase detection (e.g. "ALL RIGHT NOW CAN" before "NOW CAN" before "CAN")
  - [ ] "sorry" convention: everything before the last "sorry" in the transcript is discarded before decoding
  - [ ] One code phrase per sentence; each match yields the row's category/value pairs (categories from the `*`-prefixed header row)
  - [ ] Hour + Minute combination across two coded sentences resolves to a single time
  - [ ] Remember the last decoded result for repeat-style prompts (parity with original `last_code` behavior)
- [ ] Configuration (Story 3.4 overlap)
  - [ ] `decoder.data_path` in `config.yaml`, default `knowledge-base/effie_code.csv`
  - [ ] Copy `effie_code.csv` from the original project into `corindagpt/knowledge-base/`
- [ ] Output format: decoded secret data is appended to the transcript handed to the prompt, clearly delimited for the LLM
- [ ] Unit tests: phrase matching (incl. longest-match and modifiers), sorry-reset, card phrases, time combination, no-match passthrough

## Dev Notes
- Data confirmed by user: `effie_code.csv` (Hadley's system). Structure: col 0 = code phrase; `*Number or date`, `*Letter`, `*Playing Card Value`, objects, names, country/state/city, gem, month/day/year, color, material, coin/currency, hour, minute.
- Cards are complete in a single phrase (e.g. "COOL COULD" = King of Hearts); the original cross-row suit+value combination is not needed for this table.
- Prefix modifiers: NOW +10, SO +20, WELL +30, ALL RIGHT +40, ALL RIGHT NOW +50, ALL RIGHT PLEASE +60, ALL RIGHT THEN +70, NOW PLEASE +80, NOW THEN +90; TRY alone = 100/Joker; OKAY/COOL/WELL/ALL RIGHT + court words encode Clubs/Hearts/Spades/Diamonds courts.
