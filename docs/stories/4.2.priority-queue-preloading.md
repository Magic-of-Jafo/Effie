# Story 4.2: Enhance Audio Queue with Priority & Pre-loading

## Status
- In Progress

## Story
As a Magician, I want the audio queue to prioritize new LLM responses and support pre-loaded phrases for specific routines, so that I can perform advanced effects like the "pull-string doll".

## Acceptance Criteria
1. The audio queue functions as a priority queue. [Source: docs/prd.md#story-42]
2. Newly generated LLM response audio is inserted at the front of the queue (FR8). [Source: docs/prd.md#story-42]
3. The queue can be pre-loaded with default audio defined in `config.yaml` (FR9). [Source: docs/prd.md#story-42]
4. Pre-loaded phrases play in sequential or random order, per config. [Source: docs/prd.md#story-42]
5. The "brief input" trigger plays whichever item is at the front - prioritized LLM response or pre-loaded phrase. [Source: docs/prd.md#story-42]

## Tasks / Subtasks
- [ ] Rework `audio_queue.py`: deque of AudioItem (bytes or path), `push_front` / `append` / `play_next`, preload with sequential|random order, optional loop
- [ ] Config: `audio_queue.preload` (dir, order, loop) and `audio_queue.response_playback` ("immediate" | "queued")
- [ ] Pipeline: in "queued" mode, the LLM response is synthesized to audio and pushed to the queue front instead of playing immediately - the pull-string tap releases it
- [ ] Pre-generate TTS audio for the 11 phrases in `knowledge-base/pre_programmed_phrases.csv` (script, cached to assets)
- [ ] Tests for queue ordering, priority insertion, preload orders, loop behavior

## Dev Notes
- "queued" response mode is the pull-string doll design: the magician asks while pressing, the answer waits in the queue, and the string pull (BRIEF input) speaks it. "immediate" preserves current low-latency conversational behavior for other projects.
- Phrase audio is generated once via ElevenLabs and cached as files; regeneration only needed when the CSV or voice changes.
