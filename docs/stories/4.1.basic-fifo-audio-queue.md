# Story 4.1: Implement a Basic First-In, First-Out Audio Queue

## Status
- In Progress

## Story
As a Magician-Developer, I want a basic audio queue to store and play back generated TTS audio files sequentially, so that multiple AI responses can be handled in the order they were received without overlapping.

## Acceptance Criteria
1. An `audio_queue.py` module manages a FIFO queue of audio items. [Source: docs/prd.md#story-41]
2. Newly generated TTS audio can be added to the queue. [Source: docs/prd.md#story-41]
3. The "brief input" event triggers `play_next()`. [Source: docs/prd.md#story-41] (wired in Story 3.2)
4. `play_next()` plays the front item and removes it on success. [Source: docs/prd.md#story-41]
5. If the queue is empty, a pre-programmed default phrase is played (FR5). [Source: docs/prd.md#story-41]

## Dev Notes
- Implemented together with Story 4.2: the queue is built priority-aware from the start rather than refactored later.
- Queue items carry either raw audio bytes (LLM responses) or file paths (pre-loaded clips).
